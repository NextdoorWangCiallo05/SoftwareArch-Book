## A. 参与者与权限

- **Q-A1**：是否需要实现真实的登录认证（密码校验、会话/Token）？还是第一阶段仅通过 `reader_id` / `librarian_id` / `admin_id` 表示操作人？
- **Q-A2**：图书管理员是否需要独立的账号表，还是复用统一 `users` 表加 `role` 字段区分？
- **Q-A3**：`SystemAdmin` 是否也允许执行借书、还书操作（即管理员权限是否包含管理员代理职能）？
- **Q-A4**：权限校验失败时，接口应返回 `400`（业务错误）还是 `403`（权限不足）？统一信封中的 `code` 是否需要扩展出 `403`？

## B. 借阅证（BorrowCard）

- **Q-B1**：借阅证号生成规则是什么？建议格式 `CARD + 年份 + 6 位序号`（如 `CARD2026000001`），是否接受？
- **Q-B2**：同一读者是否允许存在多张借阅证（历史证 + 当前证）？还是全局唯一？
- **Q-B3**：借阅证是否需要"挂失/停用"状态？逾期未缴罚款时是否自动冻结借阅证？
- **Q-B4**：删除借阅证是物理删除还是置为失效状态？该读者已有未归还图书时能否删除？

## C. 读者类型与借阅规则（BorrowPolicy）

- **Q-C1**：读者类型是否只保留 UNDERGRADUATE / GRADUATE / DOCTOR / TEACHER 四种？是否需要"专科生"？
- **Q-C2**：Brief 中的借阅数量与期限（5/30、10/60、15/90、20/90）是否确认采用？
- **Q-C3**：读者类型是否允许入学后变更（如研究生升博士）？变更时已借出的图书如何处理？
- **Q-C4**：借阅规则是否需要支持"按馆藏类型叠加限制"（例如杂志最多借 2 本）？还是只看总数？

## D. 馆藏与借出物（BookTitle / LibraryItem）

- **Q-D1**：`LibraryItem` 的子类是否需要完整继承体系（Book / Magazine / Thesis），还是用 `item_type` 字段区分即可？
- **Q-D2**：馆藏副本条码（barcode）生成规则？建议 `ITEM + 年份 + 6 位序号`，是否接受？
- **Q-D3**：同一 `BookTitle` 下多副本，其中部分可借部分外借时，借书接口是否自动选择任一可借副本？
- **Q-D4**：副本状态枚举是否采用 `AVAILABLE / BORROWED / RESERVED / REMOVED` 四种？是否需要 `LOST`（遗失）？

## E. 借书与还书流程

- **Q-E1**：借书接口入参是"馆藏条码"还是"图书标题 ID"？建议按实验文档采用馆藏条码，是否接受？
- **Q-E2**：还书时是否需要校验"归还的副本确为本馆藏书且当前处于 BORROWED"？
- **Q-E3**：还书时是否需要图书管理员输入借阅证号？还是仅凭馆藏条码即可定位 Loan？
- **Q-E4**：借书成功后是否需要返回应还日期 `due_date`？字段名是否固定为 `due_date`？

## F. 预约（Reservation）

- **Q-F1**：预约是针对"图书标题"还是"具体副本"？建议针对标题（任意副本归还后通知），是否接受？
- **Q-F2**：预约是否允许多人排队？排队顺序依据 `created_at` 是否可以？
- **Q-F3**：若某读者已借有同一标题的副本，是否仍允许预约？
- **Q-F4**：预约是否需要有效期（如保留 7 天未取自动失效）？

## G. 罚款（FineRule / FineRecord）

- **Q-G1**：Brief 中各类借出物的罚款单价（0.5 / 1.0 / 0.2 / 0.5 / 2.0 元每天）是否确认？
- **Q-G2**：是否设置罚款上限（例如不超过图书定价的 2 倍）？`BookTitle` 是否需要 `price` 字段？
- **Q-G3**：罚款是否需要"缴纳"操作与缴清状态？还是只记录不处理？
- **Q-G4**：有未缴罚款时是否禁止继续借书？

## H. 第二阶段附加功能（续借、评论评分）

- **Q-H1**：续借是否要求"该图书无人预约"才可续借？
- **Q-H2**：续借次数是否设上限（如每本最多续借 1 次）？续借延长天数是否等于该读者类型的借阅期限？
- **Q-H3**：已逾期（或已归还）的记录能否续借？建议仅 `BORROWED` 且未逾期可续借，是否接受？
- **Q-H4**：图书评论评分是否需要限制"同一读者对同一标题只能评一次"，还是允许修改/多次评价？
- **Q-H5**：评论是否需要管理员审核（审核后可见）？还是发布即可见？

## I. 架构、数据与接口

- **Q-I1**：分层目录是否采用 `app/presentation`、`app/application`、`app/domain`、`app/infrastructure`？现有 `backend/app/models.py + routes.py` 是否允许重构迁移？
- **Q-I2**：现有三张表 `users / books / borrow_records` 与全量领域模型差异较大，是否允许**重建数据库**（删除旧 `library.db` 重新初始化）？
- **Q-I3**：响应信封的 `code` 是否只保留 `200/400/500` 三种，还是扩展 `404`（资源不存在）与 `403`（权限不足）？
- **Q-I4**：是否需要保留对话式 Agent 三层结构（orchestrator / circulation / skills），并将其写入架构文档？

## J. 测试、工具与教学复杂度

## 人类回答

> 回答日期：2026-09-13
> 未逐条回答的问题，按 `00-project-brief.md` 中的默认值与下述「默认取值」处理，并在 `02-requirements.md` 的「待确认问题」中登记。

### A. 参与者与权限

- **A1（已答）**：**实现真实登录认证**。用户名 + 密码校验，登录成功后返回访问令牌（token），受保护接口需携带令牌；未携带或令牌无效返回 `403`。
- **A2**：默认 **复用统一账户体系**（读者、管理员、系统管理员均通过账号登录），用 `role` 区分角色。
- **A3**：默认 **SystemAdmin 不办理借还**，借还仅由 Librarian 执行（宪法权限原则）。
- **A4（已答）**：**扩展 `403`**（权限不足/未认证）与 `404`（资源不存在）。

### B. 借阅证

- **B1**：默认采用 `CARD + 年份 + 6 位序号`，全局唯一。
- **B2**：默认 **同一读者最多持有一张有效借阅证**；旧证置为失效后允许重新办理。
- **B3**：默认 借阅证状态 `ACTIVE / LOST / REVOKED`；**不做自动冻结**（后续可扩展）。
- **B4**：默认 **逻辑删除**（置为 `REVOKED`）；存在未归还图书时拒绝注销（返回 `400`）。

### C. 读者类型与借阅规则

- **C1**：默认 四种：`UNDERGRADUATE / GRADUATE / DOCTOR / TEACHER`（不含专科生）。
- **C2**：默认 采用 5/30、10/60、15/90、20/90。
- **C3**：默认 **允许变更类型**；已借出记录保持原 `due_date` 不变，新借阅按新规则。
- **C4**：默认 **只看总数**，不按馆藏类型叠加限制。

### D. 馆藏与借出物

- **D1（已答）**：**采用继承体系** `LibraryItem` → `Book` / `Magazine` / `Thesis`（SQLAlchemy 单表继承 + `item_type` 鉴别列）。
- **D2**：默认 `ITEM + 年份 + 6 位序号`，全局唯一。
- **D3**：默认 **由系统自动选择任一 AVAILABLE 副本**；借书入参为馆藏条码（若传入标题 ID 则由服务层选副本）。
- **D4**：默认 四种状态 `AVAILABLE / BORROWED / RESERVED / REMOVED`，**不含 LOST**。

### E. 借书与还书流程

- **E1**：默认 **馆藏条码**（符合实验文档要求）。
- **E2**：默认 **需要校验**，非本馆藏书或状态非 BORROWED 时返回 `400`。
- **E3**：默认 **仅凭馆藏条码定位 Loan**，无需借阅证号。
- **E4**：默认 **返回 `due_date`**，字段名固定 `due_date`，格式 `YYYY-MM-DD`。

### F. 预约

- **F1**：默认 **针对图书标题**。
- **F2**：默认 **允许多人排队**，按 `created_at` 升序。
- **F3**：默认 **不允许**（已借有同一标题且未归还时拒绝预约）。
- **F4（已答）**：**预约设置有效期**。自创建起 **7 天**内有效，逾期自动失效（状态置为 `EXPIRED`），失效判定采用读取时惰性判定，不做定时任务。

### G. 罚款

- **G1**：默认 采用 0.5 / 1.0 / 0.2 / 0.5 / 2.0 元每天。
- **G2**：默认 **不设上限**，`BookTitle` 保留 `price` 字段（仅记录，不参与计算）。
- **G3**：默认 **只记录，提供"标记缴清"操作**（由 Librarian 执行，不涉及真实支付）。
- **G4**：默认 **有未缴罚款时禁止借书**。

### H. 第二阶段附加功能

- **H1**：默认 **有他人预约时不可续借**。
- **H2**：默认 **每本最多续借 1 次**，延长天数 = 该读者类型的借阅期限。
- **H3**：默认 **仅 `BORROWED` 且未逾期可续借**；已归还或已逾期返回 `400`。
- **H4**：默认 **同一读者对同一标题仅保留一条评论**，可修改（覆盖）。
- **H5（已答）**：**评论需审核后可见**。提交后状态为 `PENDING`，由 SystemAdmin 审核（`APPROVED` / `REJECTED`）；仅 `APPROVED` 的评论对外可见并计入平均分。

### I. 架构、数据与接口

- **I1（已答）**：**允许重构**为 `app/presentation`、`app/application`、`app/domain`、`app/infrastructure` 四层。
- **I2（已答）**：**允许删除旧 `library.db` 重建**。
- **I3（已答）**：**扩展 `403` 与 `404`**，最终 `code` 取值：`200 / 400 / 403 / 404 / 500`。
- **I4**：默认 **保留**对话式 Agent 三层结构，并写入 `07-architecture.md`。

### J. 测试、工具与教学复杂度

- **J1**：默认 **PlantUML 为主**（`.puml`）。
- **J2**：默认 要求 pytest 全通过，覆盖实验二列出的 13 类场景。
- **J3**：默认 **需要 README.md**。
- **J4**：默认 **需要** `19-ai-usage-log.md` 作为提交物。
