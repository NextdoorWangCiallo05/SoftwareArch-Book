## UC-001 注册读者账号

- **主要参与者**：Reader
- **次要参与者**：无
- **前置条件**：用户名未被占用
- **后置条件**：创建角色为 `reader` 的账户，未发放借阅证
- **基本事件流**：
  1. 读者提交用户名、密码、姓名、读者类型；
  2. 系统校验必填项与用户名唯一性；
  3. 系统对密码加盐哈希后持久化账户；
  4. 系统返回 `reader_id`。
- **异常事件流**：
  - 3a. 用户名已存在 → 返回 `400`"用户名已存在"；
  - 3b. 必填项缺失 → 返回 `400`。
- **关联需求**：FR-001、BR-015

## UC-002 登录系统

- **主要参与者**：Reader / Librarian / SystemAdmin
- **前置条件**：账户已存在且未被删除
- **后置条件**：生成有效令牌并返回给调用方
- **基本事件流**：
  1. 用户提交用户名与密码；
  2. 系统校验凭证；
  3. 系统生成令牌，返回 `token`、`user_id`、`role`、`username`。
- **异常事件流**：
  - 2a. 用户不存在或密码错误 → 返回 `403`"用户名或密码错误"。
- **关联需求**：FR-002、BR-015

## UC-003 办理借阅证

- **主要参与者**：SystemAdmin
- **次要参与者**：Reader（被办证人）
- **前置条件**：管理员已登录（UC-002）；读者账户存在；该读者当前无 `ACTIVE` 借阅证
- **后置条件**：生成状态为 `ACTIVE` 的借阅证
- **基本事件流**：
  1. 管理员输入读者标识（`reader_id` 或用户名）；
  2. 系统校验读者存在；
  3. 系统校验该读者无有效借阅证；
  4. 系统按 `CARD + 年份 + 6 位序号` 生成唯一证号；
  5. 系统持久化借阅证并返回 `card_no`。
- **备选事件流**：
  - 4a. 该读者曾持有已注销的借阅证 → 允许重新办理，生成新证号，旧证保持 `REVOKED`。
- **异常事件流**：
  - 1a. 操作者非 SystemAdmin → `403`；
  - 2a. 读者不存在 → `404`；
  - 3a. 已持有有效借阅证 → `400`。
- **关联需求**：FR-004、BR-011、BR-017

## UC-009 办理借书（重点用例）

- **主要参与者**：Librarian
- **次要参与者**：Reader（持证读者）
- **前置条件**：管理员已登录；读者持有 `ACTIVE` 借阅证
- **后置条件**：创建 `BORROWED` 状态的 Loan；副本状态置为 `BORROWED`
- **基本事件流**：
  1. 管理员提交借阅证号与馆藏条码（必要时读者需先 `<<include>> UC-002` 登录以校验身份归属）；
  2. 系统校验操作者角色为 Librarian；
  3. 系统校验借阅证存在且为 `ACTIVE`（`<<include>> UC-009A 验证借阅证`，属 UC-009 的私有子用例，不单独对外提供接口）；
  4. 系统查询该读者当前未归还数量，与读者类型上限比较（BR-002）；
  5. 系统检查是否存在超期未还记录（BR-003）；
  6. 系统检查是否存在未缴罚款（BR-006）；
  7. 系统按条码定位副本，校验存在且状态为 `AVAILABLE`；
  8. 系统按读者类型计算 `due_date`（BR-004）；
  9. 系统创建 Loan（`BORROWED`），副本状态置为 `BORROWED`；
  10. 系统返回 `loan_id`、`barcode`、`due_date`。
- **备选事件流**：
  - 7a. 若同一标题存在多本可借副本，由系统自动选择其中一本。
- **异常事件流**：
  - 2a. 操作者非 Librarian → `403`"仅图书管理员可办理借书"；
  - 3a. 借阅证不存在 → `404`；借阅证非 `ACTIVE` → `400`"借阅证无效"；
  - 4a. 达到数量上限 → `400`"借阅已满（{current}/{max}），请先归还"；
  - 5a. 存在超期未还 → `400`"有 {n} 本图书超期未还，请先归还"；
  - 6a. 存在未缴罚款 → `400`"存在未缴罚款，请先缴清"；
  - 7b. 副本不存在 → `404`；副本状态非 `AVAILABLE` → `400`"该馆藏不可借"。
- **关联需求**：FR-014、BR-001～BR-006、BR-010、BR-011

#### UC-009 结构化规格（对齐指导书参考格式）

**基本路径（Basic Path）**

| Step | 动作 |
|---|---|
| 1 | 图书管理员请求系统处理借书业务 |
| 2 | 系统显示借书处理界面（本项目为 `POST /api/circulation/borrow`） |
| 3 | 图书管理员输入借阅证信息（`card_no`） |
| 4 | 系统验证借阅证的有效性 |
| 5 | 图书管理员输入图书信息（`barcode`） |
| 6 | 系统添加新的借阅记录（Loan），并将副本状态置为 BORROWED |
| 7 | 系统显示借书后的借阅信息；管理员重复 5–7 步直至结束 |

**异常与备选路径**

| 编号 | 类型 | 触发步骤 | 系统行为 |
|---|---|---|---|
| 4a | Exception | 步骤 4 | 借阅证不存在 → `404 借阅证不存在`；借阅证非 ACTIVE → `400 借阅证无效` |
| 6a | Exception | 步骤 6 | 借阅者借书数量达到上限 → `400 借阅已满（n/max）` |
| 6b | Alternate | 步骤 6 | 书籍库存为 0 → `400 该馆藏不可借`，可转为预约（UC-013） |
| 6c | Exception | 步骤 6 | 存在超期未还 → `400 有 n 本图书超期未还` |
| 6d | Exception | 步骤 6 | 存在未缴罚款或赔偿 → `400 存在未缴罚款，请先缴清` |
| 1a | Exception | 步骤 1 | 操作者非 Librarian → `403 仅图书管理员可办理借书` |

## UC-010 申请还书与审核归还（重点用例）

> 本用例采用**读者发起申请 + 图书管理员审核**的两段式流程（BR-020），按参与者视角拆为三个子流程图。

### UC-010.1 发起归还申请（Reader）

- **主要参与者**：Reader（本人）；Librarian 可代理发起
- **前置条件**：读者已登录（`<<include>> UC-002`）；存在本人处于 `BORROWED` 的 Loan
- **后置条件**：Loan 状态置为 `RETURN_REQUESTED`；**副本状态保持 `BORROWED`**
- **基本事件流**：
  1. 读者在「我的借阅记录」对某条 `BORROWED` 记录点击「申请归还」；
  2. 系统校验调用者为该记录所属读者本人（或 Librarian）；
  3. 系统校验 Loan 当前状态为 `BORROWED`；
  4. 系统将 Loan 状态置为 `RETURN_REQUESTED`；
  5. 系统返回 `loan_id`、`title`、`status = RETURN_REQUESTED`。
- **异常事件流**：
  - 1a. Loan 不存在 → `404`；
  - 2a. 非本人且非 Librarian → `403`"只能申请归还本人的图书"；
  - 3a. 已处于 `RETURN_REQUESTED` → `400`"该图书已提交归还申请，请等待馆员审核"；
  - 3b. 状态为 `RETURNED` → `400`"该借阅记录当前状态不可申请归还"。
- **业务规则**：申请期间该记录仍计入在借数量、参与超期检查（BR-003），且不可续借（BR-012）。

### UC-010.2 审核归还申请并确认收书（Librarian）

- **主要参与者**：Librarian
- **前置条件**：管理员已登录；存在状态为 `RETURN_REQUESTED` 的 Loan
- **后置条件（审核通过）**：Loan 置为 `RETURNED`；副本置为 `AVAILABLE`；如超期则生成 `FineRecord`
- **后置条件（审核驳回）**：Loan 退回 `BORROWED`；副本状态不变；不产生罚款
- **基本事件流**：
  1. 管理员打开「还书审核」，系统列出全部待审核归还申请（含读者、书名、条码、应还日期、是否逾期）；
  2. 管理员确认已收到图书，点击「确认收书」；
  3. 系统校验操作者角色为 Librarian；
  4. 系统校验该 Loan 状态为 `RETURN_REQUESTED`；
  5. 系统设置 `return_date = 今天`，Loan 状态置为 `RETURNED`；
  6. 系统将副本状态置为 `AVAILABLE`；
  7. 若 `return_date > due_date` → `<<include>> UC-015 计算超期罚款`；
  8. 系统返回 `loan_id`、`title`、`return_date`、`overdue_days`、`fine`。
- **备选事件流**：
  - 2a. 管理员未收到图书 → 点击「驳回」→ 系统将 Loan 退回 `BORROWED`，返回 `status = BORROWED`。
- **异常事件流**：
  - 3a. 非 Librarian（含 Reader、SystemAdmin）→ `403`；
  - 4a. 该记录无待审核申请 → `400`"该借阅记录没有待审核的归还申请"。

### UC-010.3 现场办理还书（Librarian，保留通道）

- **主要参与者**：Librarian
- **前置条件**：管理员已登录；该副本存在处于 `BORROWED` 或 `RETURN_REQUESTED` 的 Loan
- **基本事件流**：
  1. 管理员在「还书办理」提交馆藏条码（读者无需先提交申请）；
  2. 系统校验操作者角色为 Librarian；
  3. 系统校验副本存在且确为本馆藏书；
  4. 系统查找该副本处于**在借**（`BORROWED` / `RETURN_REQUESTED`）的 Loan；
  5. 执行 UC-010.2 第 5～8 步（含 `<<include>> UC-015 计算超期罚款`）。
- **异常事件流**：
  - 2a. 非 Librarian → `403`；
  - 3a. 副本不存在或非本馆藏书 → `400`"非本馆藏书"；
  - 4a. 未找到未归还记录 → `400`"未找到该馆藏的借阅记录"。

**关联需求**：FR-015、FR-020、BR-005、BR-010、BR-020

## UC-011 续借图书（重点用例，P2）

- **主要参与者**：Reader（本人）或 Librarian（代理）
- **前置条件**：Loan 状态为 `BORROWED` 且未逾期；续借次数 < 1；该标题无他人有效预约（`RETURN_REQUESTED` 的记录不可续借）
- **后置条件**：`due_date` 延长一个借阅期限；`renew_count` 加 1
- **基本事件流**：
  1. 用户指定要续借的图书（`loan_id` 或标题 + 借阅记录定位）；
  2. 系统校验调用者为该读者本人或 Librarian，否则 `403`；
  3. 系统定位 Loan 并校验状态为 `BORROWED`；
  4. 系统校验未逾期（`due_date >= 今天`）；
  5. 系统校验续借次数未满（BR-012）；
  6. 系统校验该标题无他人**未过期**的 `ACTIVE` 预约（BR-008）；
  7. 系统按读者类型延长 `due_date`，`renew_count += 1`；
  8. 系统返回 `loan_id`、`new_due_date`、`renew_count`。
- **异常事件流**：
  - 3a. Loan 不存在 → `404`；状态为 `RETURNED` → `400`"该图书已归还，无法续借"；
  - 3b. 状态为 `RETURN_REQUESTED` → `400`"该图书已提交归还申请，审核通过前无法续借"；
  - 4a. 已逾期 → `400`"该图书已逾期，请归还后重新借阅"；
  - 5a. 已达上限 → `400`"该图书已达续借上限（1 次）"；
  - 6a. 存在他人预约 → `400`"该图书已被预约，暂不可续借"。
- **关联需求**：FR-016、BR-012

## UC-013 预约图书（重点用例）

- **主要参与者**：Reader
- **前置条件**：读者已登录；图书标题存在
- **后置条件**：创建 `ACTIVE` 预约并进入队列
- **基本事件流**：
  1. 读者指定图书标题；
  2. 系统校验标题存在；
  3. 系统校验该读者对该标题无 `ACTIVE` 预约；
  4. 系统校验该读者未借有同一标题且未归还；

- **异常事件流**：
  - 2a. 标题不存在 → `404`；
  - 3a. 重复预约 → `400`"您已预约过该书"；
  - 4a. 已借有同标题 → `400`"您已借有该书，无需预约"。
- **关联需求**：FR-018、BR-007～BR-009

## UC-015 计算超期罚款（重点用例，由 UC-010 包含）

- **主要参与者**：系统（在还书流程中自动执行）
- **前置条件**：Loan 已设置 `return_date` 且 `return_date > due_date`
- **后置条件**：生成 `FineRecord`，`paid = false`
- **基本事件流**：
  1. 系统计算 `overdue_days = return_date - due_date`；
  2. 若 `overdue_days <= 0` → 罚款为 0，结束；
  3. 系统按副本所属借出物类型从 `FineRule` 获取**宽限期 `grace_days`** 与**每日金额 `amount_per_day`**；
  4. 若 `overdue_days <= grace_days` → 罚款为 0（仍在宽限期内，不生成记录），结束；
  5. 系统计算 `chargeable_days = overdue_days - grace_days`，`amount = chargeable_days × amount_per_day`；
  6. 系统持久化 `FineRecord`（`paid = false`）。
- **异常事件流**：
  - 3a. 未配置对应类型的罚款规则 → `500`"未配置罚款规则"（视为系统配置错误）。
- **业务规则**：罚款计算必须委托给 `FineRule` 策略对象，禁止在路由或控制器中硬编码单价。
- **关联需求**：FR-020、BR-005

## UC-016 标记罚款缴清

- **主要参与者**：Librarian
- **基本事件流**：管理员指定罚款记录 → 校验存在且未缴 → 置 `paid = true`。

## UC-017 提交图书评分与评论（P2）

- **主要参与者**：Reader
- **前置条件**：读者已登录；图书标题存在
- **后置条件**：生成或更新评论记录，状态为 `PENDING`（待审核，不对外可见）
- **基本事件流**：
  1. 读者提交标题、评分（1–5 整数）与评论文本（可选）；
  2. 系统校验标题存在；
  3. 系统校验评分在 1–5 范围内；
  4. 若该读者对该标题已有评论 → 覆盖更新（保留原 `review_id`，状态重置为 `PENDING`）；否则新建；
  5. 系统返回 `review_id`、`rating`、`comment`、`status`。
- **异常事件流**：
  - 2a. 标题不存在 → `404`；
  - 3a. 评分越界 → `400`"评分必须为 1-5 的整数"。
- **关联需求**：FR-022、BR-013、BR-014、BR-018

## UC-022 处理赔偿（丢失馆藏）

- **主要参与者**：Librarian
- **次要参与者**：Reader（遗失人）
- **前置条件**：管理员已登录；该副本存在 `BORROWED` 状态的 Loan；图书标题已维护 `price`
- **后置条件**：生成 `LostItem`（`paid = false`）；Loan 结束；副本状态 `REMOVED`
- **基本事件流**：
  1. 管理员提交馆藏条码；
  2. 系统校验操作者角色为 Librarian；
  3. 系统校验副本存在且为本馆藏书；
  4. 系统查找该副本未归还的 Loan；
  5. 系统按出借物类型从 `CompensationPolicy` 取得赔偿倍率；
  6. 系统计算 `amount = price × rate`；
  7. 系统生成 `LostItem`，结束 Loan，副本置为 `REMOVED`；
  8. 系统返回 `lost_id`、`amount`、`lost_date`。
- **异常事件流**：
  - 2a. 非 Librarian → `403`"仅图书管理员可处理赔偿"；
  - 3a. 副本不存在 → `404`；
  - 4a. 未找到未归还记录 → `400`"未找到该馆藏的借阅记录"；
  - 6a. 标题未维护定价 → `400`"请先维护该图书定价"。
- **关联需求**：FR-027、BR-018a、BR-006
