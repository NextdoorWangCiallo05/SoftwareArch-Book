## UC-001 注册读者账号

- **主要参与者**：Reader
- **次要参与者**：无
- **前置条件**：用户名未被占用
- **后置条件**：创建角色为 `reader` 的账户，未发放借阅证
- **基本事件流**：
  1. 读者提交用户名、密码、姓名、读者类型；
  2. 系统校验必填项与用户名唯一性；
  3. 系统对密码加盐哈希后持久化账户；
  4. 系统返回 `reader_id`。
- **异常事件流**：
  - 3a. 用户名已存在 → 返回 `400`"用户名已存在"；
  - 3b. 必填项缺失 → 返回 `400`。
- **关联需求**：FR-001、BR-015

## UC-002 登录系统

- **主要参与者**：Reader / Librarian / SystemAdmin
- **前置条件**：账户已存在且未被删除
- **后置条件**：生成有效令牌并返回给调用方
- **基本事件流**：
  1. 用户提交用户名与密码；
  2. 系统校验凭证；
  3. 系统生成令牌，返回 `token`、`user_id`、`role`、`username`。
- **异常事件流**：
  - 2a. 用户不存在或密码错误 → 返回 `403`"用户名或密码错误"。
- **关联需求**：FR-002、BR-015

## UC-003 办理借阅证

- **主要参与者**：SystemAdmin
- **次要参与者**：Reader（被办证人）
- **前置条件**：管理员已登录（UC-002）；读者账户存在；该读者当前无 `ACTIVE` 借阅证
- **后置条件**：生成状态为 `ACTIVE` 的借阅证
- **基本事件流**：
  1. 管理员输入读者标识（`reader_id` 或用户名）；
  2. 系统校验读者存在；
  3. 系统校验该读者无有效借阅证；
  4. 系统按 `CARD + 年份 + 6 位序号` 生成唯一证号；
  5. 系统持久化借阅证并返回 `card_no`。
- **备选事件流**：
  - 4a. 该读者曾持有已注销的借阅证 → 允许重新办理，生成新证号，旧证保持 `REVOKED`。
- **异常事件流**：
  - 1a. 操作者非 SystemAdmin → `403`；
  - 2a. 读者不存在 → `404`；
  - 3a. 已持有有效借阅证 → `400`。
- **关联需求**：FR-004、BR-011、BR-017

## UC-009 办理借书（重点用例）

- **主要参与者**：Librarian
- **次要参与者**：Reader（持证读者）
- **前置条件**：管理员已登录；读者持有 `ACTIVE` 借阅证
- **后置条件**：创建 `BORROWED` 状态的 Loan；副本状态置为 `BORROWED`
- **基本事件流**：
  1. 管理员提交借阅证号与馆藏条码（必要时读者需先 `<<include>> UC-002` 登录以校验身份归属）；
  2. 系统校验操作者角色为 Librarian；
  3. 系统校验借阅证存在且为 `ACTIVE`（`<<include>> UC-009A 验证借阅证`，属 UC-009 的私有子用例，不单独对外提供接口）；
  4. 系统查询该读者当前未归还数量，与读者类型上限比较（BR-002）；
  5. 系统检查是否存在超期未还记录（BR-003）；
  6. 系统检查是否存在未缴罚款（BR-006）；
  7. 系统按条码定位副本，校验存在且状态为 `AVAILABLE`；
  8. 系统按读者类型计算 `due_date`（BR-004）；
  9. 系统创建 Loan（`BORROWED`），副本状态置为 `BORROWED`；
  10. 系统返回 `loan_id`、`barcode`、`due_date`。
- **备选事件流**：
  - 7a. 若同一标题存在多本可借副本，由系统自动选择其中一本。
- **异常事件流**：
  - 2a. 操作者非 Librarian → `403`"仅图书管理员可办理借书"；
  - 3a. 借阅证不存在 → `404`；借阅证非 `ACTIVE` → `400`"借阅证无效"；
  - 4a. 达到数量上限 → `400`"借阅已满（{current}/{max}），请先归还"；
  - 5a. 存在超期未还 → `400`"有 {n} 本图书超期未还，请先归还"；
  - 6a. 存在未缴罚款 → `400`"存在未缴罚款，请先缴清"；
  - 7b. 副本不存在 → `404`；副本状态非 `AVAILABLE` → `400`"该馆藏不可借"。
- **关联需求**：FR-014、BR-001～BR-006、BR-010、BR-011

## UC-010 办理还书（重点用例）

- **主要参与者**：Librarian
- **前置条件**：管理员已登录；该副本存在处于 `BORROWED` 的 Loan
- **后置条件**：Loan 置为 `RETURNED`；副本置为 `AVAILABLE`；如超期则生成 FineRecord
- **基本事件流**：
  1. 管理员提交馆藏条码；
  2. 系统校验操作者角色为 Librarian；
  3. 系统校验副本存在且确为本馆藏书；
  4. 系统查找该副本处于 `BORROWED` 的 Loan；
  5. 系统设置 `return_date = 今天`，Loan 状态置为 `RETURNED`；
  6. 系统副本状态置为 `AVAILABLE`；
  7. 若 `return_date > due_date` → `<<include>> UC-015 计算超期罚款`；
  8. 系统返回 `loan_id`、`return_date`、`overdue_days`、`fine`。
- **异常事件流**：
  - 2a. 非 Librarian → `403`；
  - 3a. 副本不存在或非本馆藏书 → `400`"非本馆藏书"；
  - 4a. 未找到未归还记录 → `400`"未找到该馆藏的借阅记录"。
- **关联需求**：FR-015、BR-005、BR-010

## UC-011 续借图书（重点用例，P2）

- **主要参与者**：Reader（本人）或 Librarian（代理）
- **前置条件**：Loan 状态为 `BORROWED` 且未逾期；续借次数 < 1；该标题无他人有效预约
- **后置条件**：`due_date` 延长一个借阅期限；`renew_count` 加 1
- **基本事件流**：
  1. 用户指定要续借的图书（`loan_id` 或标题 + 借阅记录定位）；
  2. 系统校验调用者为该读者本人或 Librarian，否则 `403`；
  3. 系统定位 Loan 并校验状态为 `BORROWED`；
  4. 系统校验未逾期（`due_date >= 今天`）；
  5. 系统校验续借次数未满（BR-012）；
  6. 系统校验该标题无他人**未过期**的 `ACTIVE` 预约（BR-008）；
  7. 系统按读者类型延长 `due_date`，`renew_count += 1`；
  8. 系统返回 `loan_id`、`new_due_date`、`renew_count`。
- **异常事件流**：
  - 3a. Loan 不存在 → `404`；状态为 `RETURNED` → `400`"该图书已归还，无法续借"；
  - 4a. 已逾期 → `400`"该图书已逾期，请归还后重新借阅"；
  - 5a. 已达上限 → `400`"该图书已达续借上限（1 次）"；
  - 6a. 存在他人预约 → `400`"该图书已被预约，暂不可续借"。
- **关联需求**：FR-016、BR-012

## UC-013 预约图书（重点用例）

- **主要参与者**：Reader
- **前置条件**：读者已登录；图书标题存在
- **后置条件**：创建 `ACTIVE` 预约并进入队列
- **基本事件流**：
  1. 读者指定图书标题；
  2. 系统校验标题存在；
  3. 系统校验该读者对该标题无 `ACTIVE` 预约；
  4. 系统校验该读者未借有同一标题且未归还；
  5. 系统创建预约（`ACTIVE`），按 `created_at` 计算排队位次，并设置 `expires_at = created_at + 7 天`（BR-008）；
  6. 系统返回 `reservation_id`、`queue_position`、`expires_at`。
- **异常事件流**：
  - 2a. 标题不存在 → `404`；
  - 3a. 重复预约 → `400`"您已预约过该书"；
  - 4a. 已借有同标题 → `400`"您已借有该书，无需预约"。
- **关联需求**：FR-018、BR-007～BR-009

## UC-015 计算超期罚款（重点用例，由 UC-010 包含）

- **主要参与者**：系统（在还书流程中自动执行）
- **前置条件**：Loan 已设置 `return_date` 且 `return_date > due_date`
- **后置条件**：生成 `FineRecord`，`paid = false`
- **基本事件流**：
  1. 系统计算 `overdue_days = return_date - due_date`；
  2. 若 `overdue_days <= 0` → 罚款为 0，结束；
  3. 系统按副本所属借出物类型从 `FineRule` 获取**宽限期 `grace_days`** 与**每日金额 `amount_per_day`**；
  4. 若 `overdue_days <= grace_days` → 罚款为 0（仍在宽限期内，不生成记录），结束；
  5. 系统计算 `chargeable_days = overdue_days - grace_days`，`amount = chargeable_days × amount_per_day`；
  6. 系统持久化 `FineRecord`（`paid = false`）。
- **异常事件流**：
  - 3a. 未配置对应类型的罚款规则 → `500`"未配置罚款规则"（视为系统配置错误）。
- **业务规则**：罚款计算必须委托给 `FineRule` 策略对象，禁止在路由或控制器中硬编码单价。
- **关联需求**：FR-020、BR-005

## UC-017 提交图书评分与评论（P2）

- **主要参与者**：Reader
- **前置条件**：读者已登录；图书标题存在
- **后置条件**：生成或更新评论记录，状态为 `PENDING`（待审核，不对外可见）
- **基本事件流**：
  1. 读者提交标题、评分（1–5 整数）与评论文本（可选）；
  2. 系统校验标题存在；
  3. 系统校验评分在 1–5 范围内；
  4. 若该读者对该标题已有评论 → 覆盖更新（保留原 `review_id`，状态重置为 `PENDING`）；否则新建；
  5. 系统返回 `review_id`、`rating`、`comment`、`status`。
- **异常事件流**：
  - 2a. 标题不存在 → `404`；
  - 3a. 评分越界 → `400`"评分必须为 1-5 的整数"。
- **关联需求**：FR-022、BR-013、BR-014、BR-018

## UC-018 查看图书评论与平均评分（P2）

- **主要参与者**：Reader（全体角色均可）
- **前置条件**：图书标题存在
- **基本事件流**：
  1. 指定图书标题；
  2. 系统筛选该标题下状态为 `APPROVED` 的评论；
  3. 系统计算平均评分（`average_rating`，保留 1 位小数，仅统计 `APPROVED`）；
  4. 系统返回评论列表与平均评分。
- **备选事件流**：
  - 2a. 无已通过评论 → `average_rating = 0.0`，`total = 0`，返回空列表（不报错）。
- **关联需求**：FR-023、BR-018

## UC-021 审核图书评论（P2）

- **主要参与者**：SystemAdmin
- **前置条件**：管理员已登录；评论存在且状态为 `PENDING`
- **后置条件**：评论状态置为 `APPROVED` 或 `REJECTED`
- **基本事件流**：
  1. 管理员指定评论与审核结论（通过 / 驳回）；
  2. 系统校验操作者角色为 SystemAdmin；
  3. 系统校验评论存在；
  4. 系统校验评论当前状态为 `PENDING`；
  5. 系统更新状态；通过则该评论对外可见并计入平均分。
- **异常事件流**：
  - 2a. 非 SystemAdmin → `403`"仅系统管理员可审核评论"；
  - 3a. 评论不存在 → `404`；
  - 4a. 已审核过 → `400`"该评论已审核"。
- **关联需求**：FR-024、BR-018
