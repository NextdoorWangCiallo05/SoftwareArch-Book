---

## 1. 文档目的

定义图书管理系统的功能需求、业务规则与非功能需求，作为后续用例建模、领域建模、架构设计、数据库设计、详细设计、编码实现与测试的唯一依据。

---

## 2. 项目目标

构建一个可运行的图书管理系统，覆盖读者注册与借阅证办理、馆藏管理、检索、借书、还书、续借、预约、罚款、评论评分与系统维护，并通过**对话式 Agent 入口**以自然语言驱动上述能力。

---

## 3. 参与者

| 参与者 | 标识 | 说明 |
|---|---|---|
| 读者（抽象） | Reader | 持有借阅证，可检索、预约、查询本人借阅信息、评论评分 |
| 学生读者 | StudentReader | 读者子类，类型：本科生 / 研究生 / 博士生 |
| 教师读者 | TeacherReader | 读者子类，类型：教师 |
| 图书管理员 | Librarian | **代理**读者办理借书、还书、标记罚款缴清；可查询任意读者借阅信息 |
| 系统管理员 | SystemAdmin | 办理/注销借阅证、维护管理员、维护图书标题与馆藏副本、维护借阅与罚款规则 |

## 4. 功能需求

### FR-001 注册读者账号（P1）

- **主要参与者**：Reader
- **前置条件**：用户名未被占用
- **描述**：读者提交用户名、密码、姓名、读者类型（本科生/研究生/博士生/教师）完成注册；密码加盐哈希存储；注册后账户角色为 `reader`，**不自动发放借阅证**。
- **验收标准**：
  1. 用户名、密码、读者类型为必填，缺失返回 `400`；
  2. 用户名重复返回 `400`；
  3. 注册成功返回 `200` 与 `reader_id`；
  4. 数据库中不存在明文密码。
- **关联规则**：BR-015

### FR-002 登录认证（P1）

- **主要参与者**：Reader / Librarian / SystemAdmin
- **描述**：提交用户名与密码，校验通过后返回 `token`、`user_id`、`role`、`username`；受保护接口需携带 `Authorization: Bearer <token>`。
- **验收标准**：
  1. 用户名不存在或密码错误统一返回 `403`，message 为"用户名或密码错误"；
  2. 登录成功返回 `200` 且 `data` 含 `token`、`user_id`、`role`；
  3. 令牌无效、过期或未携带时，受保护接口返回 `403`；
  4. **登录接口返回体在 `{code,message,data}` 信封内，不得沿用旧版 `{success,message,data}` 结构。**
- **关联规则**：BR-015、BR-016

### FR-003 注销登录（P1）

- **主要参与者**：全部已登录用户
- **描述**：使当前令牌失效。
- **验收标准**：注销后使用该令牌访问受保护接口返回 `403`。

### FR-004 办理借阅证（P1）

- **主要参与者**：SystemAdmin
- **前置条件**：读者账户存在且当前无有效借阅证
- **描述**：为指定读者生成唯一借阅证号（格式 `CARD + 年份 + 6 位序号`），状态置为 `ACTIVE`。
- **验收标准**：
  1. 非 SystemAdmin 调用返回 `403`；
  2. 读者不存在返回 `404`；
  3. 已持有有效借阅证返回 `400`；
  4. 办理成功返回 `200` 且 `data.card_no` 符合格式。
- **关联规则**：BR-011、BR-017

### FR-005 注销借阅证（P1）

- **主要参与者**：SystemAdmin
- **描述**：将借阅证状态置为 `REVOKED`（逻辑删除）。
- **验收标准**：
  1. 该读者存在未归还图书时返回 `400` 并提示先归还；
  2. 借阅证不存在返回 `404`；
  3. 注销成功后该证不可用于借书（BR-001）。

### FR-006 添加图书管理员（P1）

- **主要参与者**：SystemAdmin
- **验收标准**：非 SystemAdmin 返回 `403`；用户名重复返回 `400`；成功返回 `200` 与管理员 ID，角色为 `librarian`。

### FR-007 删除图书管理员（P1）

- **主要参与者**：SystemAdmin
- **验收标准**：管理员不存在返回 `404`；成功返回 `200`；被删除管理员的令牌立即失效。

### FR-008 添加图书标题（P1）

- **主要参与者**：SystemAdmin
- **描述**：录入题名、作者、ISBN、出版社、出版年、分类、类型（BOOK/MAGAZINE/THESIS）、定价。
- **验收标准**：非 SystemAdmin 返回 `403`；ISBN 重复返回 `400`；成功返回 `200` 与 `title_id`。

### FR-009 下架图书标题（P1）

- **主要参与者**：SystemAdmin
- **验收标准**：存在未归还副本时返回 `400`；不存在返回 `404`；成功返回 `200`（逻辑下架，不物理删除）。

### FR-010 添加馆藏副本（P1）

- **主要参与者**：SystemAdmin
- **描述**：为指定图书标题添加实体副本，生成唯一条码 `ITEM + 年份 + 6 位序号`，初始状态 `AVAILABLE`。
- **验收标准**：标题不存在返回 `404`；条码重复返回 `400`；成功返回 `200` 与 `barcode`。

### FR-011 删除馆藏副本（P1）

- **主要参与者**：SystemAdmin
- **验收标准**：副本处于 `BORROWED` 时返回 `400`；成功返回 `200`（状态置 `REMOVED`）。

### FR-012 检索图书（P1）

- **主要参与者**：Reader / Librarian / SystemAdmin
- **描述**：按关键词（题名/ISBN）、作者、分类、类型组合检索，返回可借副本数与状态，支持分页。
- **验收标准**：
  1. 返回 `total`、`page`、`page_size`、`items` 列表；
  2. 每个条目含 `title_id`、`title`、`author`、`category`、`available_count`、`status`；
  3. 无结果时返回 `200` 且 `total = 0`（不得返回 `404`）。

### FR-013 查询图书详情（P1）

- **验收标准**：标题不存在返回 `404`；成功返回 `200`，含副本列表与各副本状态。

### FR-014 办理借书（P1）

- **主要参与者**：Librarian
- **前置条件**：操作者为 Librarian；读者持有效借阅证
- **基本流程**：
  1. 校验令牌与角色（非 Librarian → `403`）；
  2. 校验借阅证存在且为 `ACTIVE`；
  3. 检查当前未归还数量是否达到该读者类型上限；
  4. 检查是否存在超期未还记录；
  5. 检查是否存在未缴罚款；
  6. 按馆藏条码定位副本，校验存在且状态为 `AVAILABLE`；
  7. 创建 Loan（状态 `BORROWED`），按读者类型计算 `due_date`；
  8. 副本状态置为 `BORROWED`。
- **验收标准**：
  1. 非 Librarian 调用返回 `403`；
  2. 借阅证无效/缺失返回 `400`；
  3. 超过数量上限返回 `400`，message 含"借阅已满"；
  4. 存在超期未还返回 `400`；
  5. 存在未缴罚款返回 `400`；
  6. 副本不存在返回 `404`，副本不可借返回 `400`；
  7. 借书成功返回 `200`，`data` 含 `loan_id`、`barcode`、`due_date`（`YYYY-MM-DD`）。
- **关联规则**：BR-001～BR-006、BR-010、BR-011

### FR-015 办理还书（P1）

- **主要参与者**：Librarian
- **基本流程**：校验角色 → 按条码定位副本（须为本馆藏书）→ 查找该副本未归还的 Loan → 设置 `return_date`、状态 `RETURNED` → 副本置 `AVAILABLE` → 若逾期且超出宽限期则计算罚款并生成 FineRecord。
- **设计说明**：指导书表述为"系统删除相应的借阅信息"，本系统采用**保留历史记录**（状态置 `RETURNED`）而非物理删除，原因：① 需支持"查询借阅信息"中的历史借阅；② 罚款记录需要外键关联借阅记录；③ 符合数据可追溯原则。该差异在实验报告中说明。
- **验收标准**：
  1. 非 Librarian 返回 `403`；
  2. 副本不存在或非本馆藏书返回 `400`；
  3. 未找到未归还记录返回 `400`；
  4. 正常还书返回 `200`，`data` 含 `loan_id`、`return_date`、`overdue_days`、`fine`；
  5. 超期还书生成罚款记录，`fine > 0`。
- **关联规则**：BR-005、BR-010、BR-011

### FR-016 续借图书（P2）

- **主要参与者**：Librarian（代理）或 Reader 本人
- **前置条件**：Loan 状态为 `BORROWED` 且未逾期；续借次数未满；该标题无他人有效预约
- **描述**：将 `due_date` 延长一个该读者类型的借阅期限，续借次数 +1。
- **验收标准**：
  1. 已归还或已逾期的记录返回 `400`；
  2. 已达续借上限（1 次）返回 `400`；
  3. 存在他人预约返回 `400`；
  4. 成功返回 `200`，`data` 含 `loan_id`、`new_due_date`、`renew_count`。
- **关联规则**：BR-012

### FR-017 查询借阅信息（P1）

- **主要参与者**：Reader（本人）/ Librarian（任意读者）
- **验收标准**：
  1. Reader 查询他人信息返回 `403`；
  2. 读者不存在返回 `404`；
  3. 支持按状态过滤（`BORROWED` / `RETURNED` / `OVERDUE`）；
  4. 返回当前借阅、历史借阅与超期状态，每条含 `loan_id`、`title`、`barcode`、`borrow_date`、`due_date`、`return_date`、`status`、`is_overdue`。

### FR-018 预约图书（P1）

- **主要参与者**：Reader
- **描述**：针对图书标题创建预约，按 `created_at` 排队；预约自创建起 **7 天**内有效（BR-008）。
- **验收标准**：
  1. 标题不存在返回 `404`；
  2. 已存在本人未过期的 `ACTIVE` 预约返回 `400`；
  3. 本人已借有同一标题且未归还返回 `400`；
  4. 成功返回 `200`，`data` 含 `reservation_id`、`queue_position`、`expires_at`（`YYYY-MM-DD`）；
  5. 已过期（`EXPIRED`）的预约不再占用排队位次，也不阻塞续借。
- **关联规则**：BR-007、BR-008、BR-009

### FR-019 取消预约（P1）

- **主要参与者**：Reader（本人）
- **验收标准**：预约不存在返回 `404`；已取消的预约重复取消返回 `400`；成功返回 `200`。

### FR-020 计算并记录超期罚款（P1）

- **主要参与者**：系统（还书时触发）
- **描述**：还书时按借出物类型对应的罚款规则计算金额：`罚款 = max(0, 逾期天数 - 宽限期) × 每日金额`；`逾期天数 ≤ 0` 时罚款为 0。
- **验收标准**：
  1. 各借出物类型的宽限期与每日金额与 `BR-005` 表格一致；
  1.1 处于宽限期内（逾期但未超宽限期）时，罚款为 0 且**不生成** `FineRecord`；
  2. 生成 `FineRecord`，含 `fine_id`、`loan_id`、`amount`、`paid`；
  3. 罚款计算逻辑必须位于 `FineRule` 策略对象内，禁止硬编码在路由中。
- **关联规则**：BR-005

### FR-021 标记罚款缴清（P1）

- **主要参与者**：Librarian
- **验收标准**：罚款记录不存在返回 `404`；已缴清重复操作返回 `400`；成功将 `paid` 置为 true 并返回 `200`；**不涉及真实支付**。

### FR-022 提交图书评分与评论（P2）

- **主要参与者**：Reader
- **描述**：对图书标题提交 1–5 的整数评分与可选评论文本；同一读者对同一标题仅保留一条（可覆盖修改）。提交后状态为 `PENDING`，**审核通过后才对外可见**。
- **验收标准**：
  1. 评分为 0、6 或非整数返回 `400`，message 含"评分必须为 1-5 的整数"；
  2. 标题不存在返回 `404`；
  3. 成功返回 `200`，`data` 含 `review_id`、`title_id`、`rating`、`comment`、`status`（`PENDING`）；
  4. 重复评价时更新原记录，且 `review_id` 保持不变，状态重新置为 `PENDING` 需再次审核。
- **关联规则**：BR-013、BR-014、BR-018

### FR-023 查看图书评论与平均评分（P2）

- **主要参与者**：全部角色
- **描述**：返回**已审核通过（`APPROVED`）**的评论列表与平均评分。
- **验收标准**：
  1. 返回 `200`，`data` 含 `title_id`、`average_rating`、`total`、`reviews` 列表；
  2. `average_rating` 保留 1 位小数，仅统计 `APPROVED` 记录；无已通过评论时为 `0.0`；
  3. `reviews` 每条含 `review_id`、`username`、`rating`、`comment`、`created_at`；
  4. `PENDING` / `REJECTED` 的评论不出现在列表中，也不计入平均分。

### FR-024 审核图书评论（P2）

- **主要参与者**：SystemAdmin
- **描述**：对 `PENDING` 状态的评论执行通过（`APPROVED`）或驳回（`REJECTED`）。
- **验收标准**：
  1. 非 SystemAdmin 返回 `403`；
  2. 评论不存在返回 `404`；
  3. 对非 `PENDING` 状态的评论重复审核返回 `400`；
  4. 审核成功返回 `200`，`data` 含 `review_id`、`status`；
  5. 审核通过后该评论立即对外可见并计入平均分。

### FR-025 维护借阅规则（P1）

- **主要参与者**：SystemAdmin
- **描述**：按读者类型维护最大借阅数量与借阅期限。
- **验收标准**：非 SystemAdmin 返回 `403`；数量 ≤ 0 或期限 ≤ 0 返回 `400`；成功返回 `200`；修改后新借阅按新规则生效。
- **关联规则**：BR-002、BR-004

### FR-026 维护罚款规则（P1）

- **主要参与者**：SystemAdmin
- **描述**：按借出物类型维护每日罚款金额与宽限期天数。
- **验收标准**：非 SystemAdmin 返回 `403`；金额为负或宽限期为负返回 `400`；成功返回 `200`。
- **关联规则**：BR-005

### FR-027 处理赔偿（丢失馆藏）（P1）

- **主要参与者**：Librarian
- **前置条件**：该副本存在处于 `BORROWED` 的 Loan；图书标题已维护 `price`
- **描述**：读者遗失馆藏时，管理员登记丢失；系统按赔偿策略计算赔偿金额，生成 `LostItem` 赔偿记录，结束对应 Loan，副本状态置为 `REMOVED`。
- **基本流程**：
  1. 校验操作者为 Librarian；
  2. 按条码定位副本与本馆藏书；
  3. 查找未归还 Loan（不存在 → `400`）；
  4. 按出借物类型从 `CompensationPolicy` 取得赔偿倍率，`amount = price × rate`；
  5. 生成 `LostItem`（`paid = false`），Loan 结束，副本置 `REMOVED`。
- **验收标准**：
  1. 非 Librarian 返回 `403`；
  2. 副本不存在 → `404`；未找到未归还记录 → `400`；
  3. 标题未维护定价 → `400`"请先维护该图书定价"；
  4. 成功返回 `200`，`data` 含 `lost_id`、`loan_id`、`amount`、`lost_date`；
  5. 存在未缴赔偿时禁止借书（BR-006）。
- **关联规则**：BR-019、BR-010、BR-011

### FR-028 管理借阅者（P1）

- **主要参与者**：SystemAdmin
- **描述**：对读者信息进行增加、删除（停用）、查询、修改（对应图 1「管理借阅者」）。
- **验收标准**：
  1. 非 SystemAdmin 返回 `403`；读者不存在返回 `404`；
  2. 修改支持姓名、读者类型、邮箱、电话；
  3. **删除采用停用**（`status = inactive`），存在未归还图书时拒绝停用（`400`）；
  4. 查询支持按用户名/姓名/读者类型过滤与分页。
- **关联规则**：BR-011

### FR-029 管理图书管理员（P1）

- **主要参与者**：SystemAdmin
- **描述**：在 FR-006 / FR-007 基础上补充**查询与修改**管理员信息（对应图 1「管理图书管理员」）。
- **验收标准**：非 SystemAdmin 返回 `403`；管理员不存在返回 `404`；修改支持姓名、工号；列表支持分页。

### FR-030 修改图书信息（P1）

- **主要参与者**：SystemAdmin
- **描述**：修改已存在图书标题的信息（题名、作者、出版社、出版年、分类、定价、位置），对应图 1「管理图书 → 修改图书」。
- **验收标准**：非 SystemAdmin 返回 `403`；标题不存在返回 `404`；ISBN 不可修改；成功返回 `200` 与更新后的标题信息。

## 5. 业务规则

### BR-001 借阅证有效性
借书前必须校验借阅证存在且状态为 `ACTIVE`；`LOST` / `REVOKED` 一律拒绝借书。

### BR-002 借阅数量上限
策略键为 **`(reader_type, item_type)` 二维**（对应参考类图的"借书策略"继承体系）：

| reader_type | ALL / BOOK | MAGAZINE | THESIS |
|---|---|---|---|
| ASSOCIATE（专科生） | 3 | 2 | 2 |
| UNDERGRADUATE（本科生） | 5 | 2 | 2 |
| GRADUATE（研究生） | 10 | 2 | 2 |
| DOCTOR（博士生） | 15 | 2 | 2 |
| TEACHER（教师） | 20 | 2 | 2 |

达到上限拒绝借书；查找顺序：先 `(reader_type, item_type)` 精确匹配，未命中回退 `(reader_type, ALL)`。

### BR-003 超期未还检查
存在任一 `BORROWED` 且 `due_date < 今天` 的记录时，拒绝新借书。

### BR-004 借阅期限
`due_date = borrow_date + 借阅期限`，策略键同为 **`(reader_type, item_type)` 二维**（对应参考类图的"书到期策略 / 杂志到期策略"）：

| reader_type | ALL / BOOK | MAGAZINE | THESIS |
|---|---|---|---|
| ASSOCIATE / UNDERGRADUATE | 30 | 7 | 3 |
| GRADUATE | 60 | 7 | 3 |
| DOCTOR / TEACHER | 90 | 7 | 3 |

### BR-005 罚款规则（按借出物类型）

| 借出物类型 | 宽限期（天） | 每日罚款 |
|---|---|---|
| CHINESE_BOOK | 0 | 0.5 元 |
| FOREIGN_BOOK | 3 | 1.0 元 |
| CHINESE_MAGAZINE | 0 | 0.2 元 |
| FOREIGN_MAGAZINE | 2 | 0.5 元 |
| THESIS | 0 | 2.0 元 |

**计费规则**：超期罚款由「宽限期 + 每日罚金」两部分组成（指导书：超期时间的规定和罚金都不同）。

```text
逾期天数     = return_date - due_date
计费天数     = max(0, 逾期天数 - grace_days)
罚款金额     = 计费天数 × amount_per_day
```

- 逾期天数 ≤ 0：无罚款；
- 逾期天数 > 0 但 ≤ `grace_days`：**判定为超期（计入超期未还检查），但不产生罚金**；
- 逾期天数 > `grace_days`：按超出部分计费。

### BR-006 未缴罚款 / 未缴赔偿禁止借书
存在 `paid = false` 的罚款记录**或未缴赔偿记录**时拒绝借书。

### BR-007 预约唯一性
同一读者对同一标题最多存在一条 `ACTIVE` 预约。

### BR-008 预约排队与有效期
同一标题的 `ACTIVE` 预约按 `created_at` 升序排队，`queue_position` 从 1 开始。
预约有效期为 **7 天**（`expires_at = created_at + 7 天`）；超过有效期的预约视为 `EXPIRED`：
- `EXPIRED` 预约不占用排队位次；
- `EXPIRED` 预约不阻塞续借（BR-012）；
- 失效判定采用**读取时惰性判定**，系统不做定时清理任务。

### BR-009 已借不可预约
读者已借有同一标题且未归还时，不得预约该标题。

### BR-010 副本状态机
`AVAILABLE → BORROWED → AVAILABLE`；`AVAILABLE → RESERVED → AVAILABLE|BORROWED`；任意状态 → `REMOVED` 后不可再借。

### BR-011 权限矩阵

| 功能 | Reader | Librarian | SystemAdmin |
|---|---|---|---|
| 注册 / 登录 | ✔ | ✔ | ✔ |
| 检索、查看评论 | ✔ | ✔ | ✔ |
| 预约、取消预约、评论评分 | ✔ | ✘ | ✘ |
| 查询本人借阅信息 | ✔ | ✔ | ✘ |
| 查询任意读者借阅信息 | ✘ | ✔ | ✘ |
| 借书、还书、续借、标记罚款缴清 | ✘ | ✔ | ✘ |
| 借阅证、管理员、图书、规则维护 | ✘ | ✘ | ✔ |
| 审核图书评论 | ✘ | ✘ | ✔ |

### BR-012 续借条件
仅 `BORROWED` 且未逾期可续借；每本最多续借 1 次；延长天数 = 该读者类型的借阅期限；存在他人有效预约时不可续借。

### BR-013 评分范围
评分必须为 1–5 的整数，越界为业务错误（`400`）。

### BR-014 评论唯一性
同一读者对同一标题仅保留一条评论，重复提交视为更新；更新后状态重置为 `PENDING`，需重新审核。

### BR-015 认证规则
密码加盐哈希存储；登录成功返回令牌；受保护接口校验令牌与角色；角色从令牌解析，不信任请求体中的角色字段。

### BR-016 状态码语义
`200` 成功；`400` 业务错误；`403` 未认证/权限不足；`404` 资源不存在；`500` 系统错误。

### BR-017 借阅证注销条件
存在未归还图书时不得注销借阅证。

### BR-018a 赔偿规则
赔偿金额 `amount = BookTitle.price × CompensationPolicy.rate`，倍率按出借物类型：

| 出借物类型 | 赔偿倍率 |
|---|---|
| BOOK（中外文图书） | 2.0 倍 |
| MAGAZINE（中外文杂志） | 1.5 倍 |
| THESIS（论文） | 3.0 倍 |

- 未维护定价的图书登记丢失时拒绝（`400`）；
- 赔偿记录 `paid = false` 时禁止借书（同 BR-006）；
- 赔偿计算必须委托 `CompensationPolicy` 策略对象，禁止硬编码倍率。

### BR-018 评论审核规则
评论状态机：`PENDING → APPROVED | REJECTED`。
- 仅 `APPROVED` 评论对外可见，并计入 `average_rating`；
- 审核由 SystemAdmin 执行，读者本人与 Librarian 均无审核权限；
- 作者本人可查看自己的 `PENDING` / `REJECTED` 评论（不在公开列表中返回）。

## 6. 非功能需求

- **NFR-001 安全性**：密码加盐哈希存储；令牌可失效；不返回密码等敏感字段。
- **NFR-002 可维护性**：严格四层分层，业务规则集中在策略/领域对象，Controller 不放业务规则。
- **NFR-003 可测试性**：核心用例通过 pytest + httpx 覆盖，测试使用独立 SQLite 库，不污染运行库。
- **NFR-004 易用性**：错误信息可直接呈现给最终用户（中文、具体、可行动）。
- **NFR-005 一致性**：日期统一 `YYYY-MM-DD`；金额统一 `Decimal`/浮点保留 2 位；统一响应信封。
- **NFR-006 可移植性**：SQLite 免安装；依赖写入 `requirements.txt`，`pip install -r` 即可运行。
